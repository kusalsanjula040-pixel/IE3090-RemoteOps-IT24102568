## 1. Project Overview

RemoteOps is a remote system monitoring and management tool implemented in C using the standard BSD sockets API.

The system consists of two main programs:

* **Agent** — the server program running on the managed Linux machine.
* **Controller** — the client program used by an administrator to communicate with the Agent.

The main control communication channel uses **TCP/IP**. A secondary **UDP** channel is used for periodic system monitoring when monitoring is enabled.

The implementation supports:

* Multiple simultaneous Controller connections
* Authentication
* System information monitoring
* Process listing
* Restricted remote command execution
* File upload
* File download
* UDP-based periodic monitoring
* Graceful disconnection
* Logging
* Personalised protocol responses

## 3. Architecture

RemoteOps uses a client/server architecture.

```text
                    TCP/IP
        +----------------------------+
        |                            |
        |       Controller           |
        |        TCP Client          |
        |                            |
        +-------------+--------------+
                      |
                      | TCP Commands
                      |
                      v
        +-------------+--------------+
        |                            |
        |          Agent             |
        |        TCP Server          |
        |                            |
        |        Port: 9410          |
        |                            |
        +-------------+--------------+
                      |
        +-------------+-------------+
        |             |             |
        v             v             v
     SYSINFO       LISTPROC        EXEC
        |
        |
        v
   File Storage
./agentfiles/IT24102568/

        ^
        |
        | UDP Monitoring
        |
        +----------------------------+
                     |
                     v
                Controller
```

The Agent listens for incoming TCP connections on port **9410**.

Each accepted Controller connection is handled independently using a POSIX thread (`pthread`). This allows multiple Controllers to communicate with the same Agent concurrently.

---

## 4. Concurrency Model

The Agent uses a **thread-per-client** concurrency model.

When a new Controller connects:

1. The Agent accepts the TCP connection.
2. A client context is created.
3. A new POSIX thread is created using `pthread_create()`.
4. The new thread handles the connected Controller independently.
5. The thread is detached so that its resources can be automatically released when it terminates.
6. The main Agent thread continues listening for new connections.

This design prevents one Controller connection from blocking the main listening loop.

The project uses:

```c
pthread_create()
```

and is compiled with:

```text
-pthread
```

The Agent is designed to support at least five simultaneous Controller connections for testing, as required by the assignment.

## 14. EXEC — Restricted Command Execution

RemoteOps does **not** allow arbitrary shell command execution.

The Agent supports exactly the following whitelisted commands:

```text
DATE
UPTIME
DISKFREE
HOSTNAME
WHOAMI
```

Examples:

```text
EXEC DATE
```

```text
EXEC UPTIME
```

```text
EXEC DISKFREE
```

```text
EXEC HOSTNAME
```

```text
EXEC WHOAMI
```

The Agent checks the requested command against the fixed whitelist before executing it.

For example:

```text
EXEC ls
```

must be rejected because `ls` is not included in the permitted command whitelist.

Expected response:

```text
ERR 002 COMMAND_NOT_ALLOWED SID:8652
```

This restriction prevents arbitrary shell commands from being executed remotely.

## 27. TCP and UDP Responsibilities

RemoteOps separates control communication from periodic monitoring communication.

### TCP

TCP is used for:

* Authentication
* SYSINFO
* LISTPROC
* EXEC
* PUT
* GET
* MONITOR START
* MONITOR STOP
* QUIT

TCP provides reliable and ordered delivery for the control operations and file transfers.

### UDP

UDP is used for:

* Periodic system monitoring datagrams

UDP is suitable for periodic monitoring because monitoring updates can be transmitted independently without requiring a reliable connection for every monitoring update.

---

## 28. Protocol Framing

The RemoteOps TCP protocol uses a line-based text protocol.

Normal commands and responses are terminated using:

```text
\n
```

For example:

```text
AUTH OPS-2568\n
```

The Agent must handle TCP stream behaviour correctly because one `recv()` call does not necessarily correspond to one complete command.

The implementation therefore needs to correctly handle:

* Partial lines
* Multiple commands received together
* Newline-terminated commands
* Raw file bytes following `PUT`
* Raw file bytes following `GET`

File transfers are handled using the required byte count rather than assuming that a single `send()` or `recv()` transfers the complete file.
